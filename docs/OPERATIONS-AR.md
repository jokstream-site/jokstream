## 2. الأسرار والمتغيرات

### jokflix
الأسماء المعروفة من README الحالي:
- `TMDB_TOKEN` — Bearer token، يفضّل.
- `TMDB_API_KEY` — بديل API key.

تُحفظ في Cloudflare Worker Secrets/Bindings الخاصة بـ jokflix. لا تضعها في:
- app.js أو index.html.
- ملفات docs.
- GitHub commits أو issues.
- روابط URL أو query strings.
- سجلات Console.

### jokstream-api
الخدمة تستخدم موارد D1 وKV وبيانات اعتماد لمزود القنوات/الترجمات حسب إعدادها الحالي. لا يفترض هذا الدليل أسماء secrets أو binding IDs غير المؤكدة. لا تغيّر bindings أو الأسرار أو قواعد البيانات.

### الواجهة
لا يحتاج المتصفح إلى TMDB secret. الثوابت العامة في app.js:
- `JOKFLIX_API`
- `JOKSTREAM_API`
- `TMDB_IMAGE`
- `VIDSRC_HOSTS` / `VIDSRC`

هذه عناوين عامة وليست أسراراً. لا تضع مفاتيح خاصة بجانبها.

## 3. ملفات الواجهة ومسؤولية كل ملف

| الملف | الوظيفة | متى نعدله؟ |
|---|---|---|
| index.html | عناصر الصفحة، IDs، النوافذ، ترتيب تحميل scripts | إضافة/تغيير عنصر واجهة |
| app.js | منطق التطبيق وربط الأحداث وAPI | سلوك التطبيق |
| style.css | التصميم والاستجابة | الشكل والتخطيط |
| manifest.json | تعريف PWA | الاسم والأيقونات |
| pwa-sw.js / sw.js | التخزين المؤقت وسلوك service worker | فقط بعد فحص أثر cache |
| icons/* | الأيقونات | تغيير الهوية البصرية |
| docs/* | وثائق النظام | بعد كل تعديل مؤثر |

أي ID يستخدمه app.js يجب أن يكون موجوداً في index.html. عند تغيير ID راجع الملفين معاً.

## 4. طريقة تغيير آمنة

1. اكتب طلب التغيير وحدد الملف/الخدمة المتأثرة.
2. تحقق من آخر commit على main.
3. أنشئ فرع backup باسم وتاريخ واضحين من commit المعروف أنه يعمل.
4. اقرأ الملفات الحالية من GitHub قبل التحرير؛ لا تعتمد على نسخة قديمة في الذاكرة أو محادثة.
5. غيّر أصغر نطاق ممكن.
6. افحص diff وتأكد من عدم حذف event listeners أو IDs أو وظائف live.
7. لا تخلط تغيير التصميم مع تغيير API أو المشغل.
8. حدّث رقم cache-busting في index.html عند تغيير app.js أو style.css إذا كان أسلوب النشر الحالي يعتمد عليه.
9. انشر Worker الواجهة فقط إذا كانت التغييرات تتطلب ذلك.
10. اختبر الوظيفة المعدلة وكل الوظائف الحساسة المجاورة.
11. سجّل commit SHA ونتيجة الاختبارات في docs/KNOWN-GOOD-BASELINE.md أو سجل تغيير منفصل.

## 5. النشر

الموقع الحالي يخدمه Cloudflare Worker اسمه jokstream-site. النسخة المنشورة التي سبق التحقق منها كانت تحتوي HTML/JS/CSS كأصول مضمّنة داخل bundle الخاص بالـ Worker. لذلك:
- commit في GitHub وحده لا يثبت أن Worker تم تحديثه.
- يجب التأكد من طريقة نشر Worker الفعلية في حساب Cloudflare قبل أي نشر.
- عند استخدام آلية bundle multipart، يجب الحفاظ على metadata وbindings الحالية وملف worker.js، وتحديث الأصول المقصودة فقط.
- لا تستبدل worker.js أو metadata بتخمينات أو قالب جديد.
- بعد النشر أعد قراءة bundle المنشور وتأكد أن محتوى /app.js و/index.html يطابق النسخة المطلوبة.
- لا تنشر jokstream-api ضمن عملية نشر الموقع.

## 6. Cache وPWA

قد تبقى نسخة قديمة في:
- Cloudflare edge cache.
- cache المتصفح.
- service worker.
- cache query string للملف JS/CSS.

عند نشر تغيير:
1. راجع query version في index.html.
2. افتح الموقع مع query refresh فريد مثل `?refresh=YYYYMMDD-N`.
3. تحقق من تحميل app.js بالإصدار المتوقع في DevTools Network.
4. إذا استمر السلوك القديم، اختبر نافذة خاصة قبل حذف بيانات PWA.
5. لا تحذف service worker أو cache عشوائياً؛ قد يغير ذلك تجربة التثبيت.
